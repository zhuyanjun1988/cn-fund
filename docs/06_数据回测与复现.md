# 数据口径、回测和复现

## 1. 公开版能复现什么

公开仓库支持两层复现：

1. 用合成数据验证策略规则、季度调仓、成本会计和失败关闭；
2. 从发布的 2740 日会计账本独立重算 CAGR、最大回撤、静态压力、路径叠加压力、
   权重和与负权重检查。

公开版**不能**从零重新抓取并生成全部 2015—2026 历史结果，因为第三方原始响应、
PDF、行情数据库和完整内部内容寻址副本没有再分发。

## 2. 历史输入的概念口径

每个资产袖套需要：

- 日级总回报或基金累计净值；
- 分红、拆分和复权语义；
- 估值历史及其 `as_of`、`known_at`；
- 共同交易日历；
- 产品申购、赎回、限购和生命周期证据；
- 费率、佣金、价差、溢价和结算假设。

回放只应在决策时使用当时已知数据。基金调整日或指数估值日与实际可得时间不同
时，应使用更晚的 `known_at`。只记录发布日期而不记录收到时间，无法证明点时。

## 3. 总回报语义

历史代理必须反映现金分红和份额拆分。只用未复权单位净值会漏掉分红收益；直接
使用供应商最终累计净值又可能包含后来修订。原研究对固定代理确认了 18 个分红
事件和 1 个拆分事件，总回报语义与回放一致。

公开账本只保留组合层 NAV 和每日权重，不包含可再分发的全部底层净值。它适合
验证会计结果，不足以审计每只基金的原始供应商数据。

## 4. 点时数据的真实限制

G6 在每个决策中严格选择调整日前的估值记录，这是必要条件，但不是充分条件。
估值序列由 2026 年回溯抓取，供应商可能重算历史或修订指数数据；没有逐日同期
原始快照，就不能证明 2015 年的研究者当时能看到完全相同的历史序列。

因此标签必须是 `formation-contaminated`，不能因“代码使用了 shift/严格小于”
就升级为 clean PIT 或 OOS。

## 5. 回放会计

每日先按底层资产总回报对上日权重做市值漂移：

```text
gross_return = Σ(weight_previous × level_today / level_previous)
NAV_today_before_trade = NAV_previous × gross_return
drifted_weight_i = weight_previous_i × relative_return_i / gross_return
```

交易日再从漂移权重调整到目标权重，按双边绝对变化收取成本。交易后现金、权益、
黄金和债券权重必须非负且总和为 1。场外赎回等待的敏感性使用固定经济事件，避免
因结算测试重新产生信号。

## 6. 公开证据文件

`evidence/g6-standard-1/daily_accounting_ledger.json` 包含：

- 2740 个交易日；
- 每日组合净值和收益；
- 八个袖套权重；
- 调仓前/后静态压力；
- 当前倾斜的出资者和接收者。

SHA-256：

```text
ea9a4e7d2026a47645bd06e109213ff810ca9a83acbebb760be36332c1c701b2
```

`public_result_summary.json` 保存发布目标、原内部关键工件哈希和风险裁决。验证器
先检查账本哈希，再逐行重算并按 `1e-36` 容差比较 Decimal 指标。

## 7. 运行验证

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
make test PYTHON=.venv/bin/python
make verify-evidence PYTHON=.venv/bin/python
```

测试包括：

- 战略权重和 2.5% 倾斜不变量；
- 找不到完整接收者/出资者时回归基础目标；
- 0% HK 可接收但不可出资；
- 合成 900 交易日的季度回放和结算桥；
- 前向 HOLD 计划的哈希和金额一致性；
- 公开账本指标、风险日期和负权重检查。

## 8. 没有上传的内容

- 原始 HTTP 响应、网页、PDF 和第三方数据；
- 本地 SQLite/Parquet、Futu/腾讯等行情副本；
- 可能受许可限制的指数历史；
- 账户、cookies、token、浏览器状态；
- 内部 append-only 审计账本和 74 MB 内容寻址重复副本；
- 与 G6 无关或已淘汰的数千个中间合同。

不上传这些内容是发布范围选择，不等于原研究完整可由公众独立重建。README 和
代码不会作出超出公开证据的可复现承诺。

## 9. 如果要做严格重现

需要在遵守数据许可的前提下重建：

1. 每个基金和指数的原始来源合同；
2. 带收到时间的不可变原始快照；
3. 分红、拆分、指数方法和产品事件；
4. 决策日前可得估值；
5. 当时产品份额、费率、限购和结算；
6. 固定代码 commit、合同和数据哈希；
7. 从原始输入到日账本和公开摘要的完整流水线。

这属于后续 P1/P2 研究基础设施，不应阻止当前负结果和核心代码的公开交付。
